# 训练协议与可复现运行

状态：2026-10-03。此文档记录**已实现的训练代码和固定协议**。量化结果由 `outputs/evaluation/` 的冻结选择与测试报告生成后另行发布。源数据、缓存和权重均在本机 `outputs/`，被 `.gitignore` 排除。

## 1. 时间和样本

所有时刻为 UTC。源 5m `date` 是 K 线开盘时间；每整点用截至该整点已完成的 5m bar 决策，等待完整 5 分钟，在整点后 5 分钟的 bar 开盘价模拟执行。主标签跟踪从此成交价起 48 根 5m bar 的上/下实现半方差，策略隔 4 小时调整；实际账本出场价为下次执行 bar 开盘价。

| 用途 | 决策时间 | 有效 `(小时, 合约)` 键 | 特别约束 |
|---|---|---:|---|
| 训练 | 2023-01-08 01:00 至 2025-06-30 19:00 | 260,580 | 起始前 7 日作特征预热；标签结束须不晚于 2025-07-01 |
| 验证前段/校准 | 2025-07-01 00:00 至 2025-10-31 19:00 | 35,376 | 早停及由预测分数到执行收益的线性校准 |
| 验证后段/选择 | 2025-11-01 00:00 至 2026-01-31 19:00 | 26,448 | 只在此段选候选和交易阈值 |
| 测试 | 2026-02-01 00:00 至 2026-09-24 19:00 | 67,920 | 仅在选择文件冻结后评估一次；每个标签完整成熟 |

验证合计 61,872 键。所有合约同一时间边界，不随机拆分。训练每轮交替用两组整点相位（每轮约 130,290 键），减少重叠标签的单轮重复；验证和测试使用全部有效整点。标签终止时间为决策后 4 小时 5 分，边界据此清除未成熟样本。四小时策略有四个互不重叠的整点相位，分别计账并报告均值和最差相位。

## 2. 已实现输入和标准化

`src/crypto_timing/cache.py` 逐合约核查 5m 网格、OHLC 不等式、成交非负及主动买额范围。从原始字段因果构造：

- **快序列**：过去 288 根 5m × 31 通道，含收益/实体/影线/区间、成交量和笔数、主动买卖代理、VWAP、历史动量与波动、历史半方差、成交 surprise、BTC/ETH 与 12 币市场广度/离散度及 UTC 周期。
- **慢序列**：过去 168 个已完成小时 × 20 通道，含 1h/4h/24h/7d 状态。
- **显式统计**：16 个快通道各取末值、最近 1h 均值、4h 均值、24h 均值和 24h 标准差，共 80 维。
- **市场状态**：BTC/ETH 动量/波动、广度/离散度及本币对 BTC 的过去 7 日 beta、残差、相关，共 10 维。

每个值通道有独立有效性 mask。对每合约每通道，**仅用训练期**样本拟合中位数与 `IQR/1.349`，标准化后截到 `[-8,8]`；无观测值在数值张量置零，同时保留 mask。快序列取训练期每小时一个样本估计分位数，变换应用于所有 5m。预热不足处不进入训练。当前版本没有盘口、OI、链上、mark/index 或 funding 作为模型输入；资金费率仅在策略事后账本按历史结算事件计入。

## 3. 网络与目标

代码 `src/crypto_timing/model.py` 的标准版实测 **214,470 参数**：快分支 d=64、三层因果深度卷积（核 3/9/25、扩张 1/2/4）；慢分支 d=64、两层因果卷积；两路各做末态、均值、attention 汇总，快分支另保留末尾 4h 均值；80 维统计和 10 维市场状态经轻 MLP；状态门控融合到 d=128，再经两层残差 MLP，输出半方差 logit、相对波动和风险调整终点收益。慢分支目前采用**attention pooling**，未加入设计稿候选中的自注意力层；其必要性需看现有结构结果后再判断。

研究组：4h 有界半方差不对称 `A`、4h 对数半方差比 `L`、1h `A`、4h 终点风险调整收益 `R`、4h 联合 `A+R+V`；另跑联合目标不同种子、两层快 TCN、无市场状态和无显式统计对照。损失均为 SmoothL1 的固定组合，具体权重见 `src/crypto_timing/training.py`。使用 AdamW（学习率 `3e-4`、weight decay `1e-4`）、dropout `0.1`、批量 256、bf16 autocast、梯度范数裁剪 1、最多 6 轮；验证前段无改善连续 2 轮则停止，保存最优与每轮最近检查点。首轮 GPU 为 RTX 5060 Laptop 8 GB。

表格基线使用相同快序列末态、慢序列末态、统计和市场特征：Ridge `alpha=1000`；LightGBM 最大 700 轮、31 叶、`min_data_in_leaf=300`，在验证前段提前停止。规则基线为 4h 动量、历史半方差不对称、固定持有与空仓。后段验证以历史预测校准执行收益，阈值网格固定为往返假设成本的 `0/0.25/0.5/1/1.5` 倍；要求四相位平均参与率至少 5%，并以平均净 Sharpe 选阈值与候选。如果没有策略胜过空仓，则交易选择为**空仓**，仍记录预测表现最好的模型作为诊断。

账本的主要成本是**情景假设**：单边 4bp 手续费 + 2bp 滑点，另按历史结算事件计入 funding。它不是从账户费率或逐笔盘口证明的真实成交成本；测试另报告单边 0/1/3/6/10bp 的固定阈值敏感性。持仓在四小时相位内持续，换仓以 `abs(new-old)` 计单边成本，最后强制平仓。

## 4. 复现命令

在 Windows PowerShell 中：

```powershell
& 'D:/Total_Tools/miniforge3/Scripts/activate'
conda activate universal
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python scripts/build_cache.py
python scripts/run_baselines.py
python scripts/train_network.py --mode joint4h --output outputs/models/joint4h_seed20261003
./scripts/run_experiments.ps1
python scripts/select_models.py
python scripts/final_test.py
python -m pytest -q
```

`scripts/run_experiments.ps1` 跳过已存在 `summary.json` 的完成运行，可从下一组继续。每组保留 `history.jsonl`、控制台日志、`last.pt`、`best.pt`、训练汇总与验证预测；`last.pt` 可按同配置从最近轮继续。对测试期的推理只读取已冻结的 `outputs/evaluation/selection.json`，不会修改它。

## 5. 当前协议边界

成本与可执行性仍是情景模拟；没有订单簿、逐笔成交、真实下单延迟或账户实际费率。`funding_rate` 的事件时间作为结算近似，开平仓与结算相差 5 分钟以上，但仍需按实际账户流水审计。[Binance 官方说明](https://www.binance.com/en/support/faq/detail/98488a516eb84e3eb34605683dffd554)确认资金费仅对结算时持仓收付，且具体合约结算频率可能不同；[官方资金费率说明](https://www.binance.com/en/support/faq/detail/360033525031)提到结算时点可能有约 15 秒偏移。这里没有用未来资金费率作为模型特征。

多币高度相关、4h 标签相邻重叠、历史仅约 3.7 年；逐键相关或四相位 Sharpe 不能当作独立交易机会的精确置信度。任何显著性结论需按连续日期块或更长时间单位计算，并在真正未来数据中复验。
